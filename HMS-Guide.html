Section 1

My Medical Manager Files My Work — 15 Java files + 3 data files

GUI — package gui.manager
ManagerDashboard.java
The main window that opens after a Medical Manager logs in.
Shows a welcome bar with the manager's username, five tabs (My Profile, Departments, Doctor Schedules, Assessment Types, Reports), and a Logout button.
ProfilePanel.java
Lets the signed-in manager view and update their own display name.
Loads the manager record from medicalManagers.txt using MedicalManagerService. Username, status, and password are read-only here — those are Admin-owned.
DepartmentPanel.java
Full create/update screen for hospital departments.
Table shows all departments; clicking a row loads it into the form. Supports Add, Update (status to ACTIVE/INACTIVE), Find by ID, Refresh, Clear.
DoctorSchedulePanel.java
Build and manage doctors' working schedules.
Add new slots (date + start/end time), update existing ones, filter by doctor ID or show only AVAILABLE slots. Blocks editing of BOOKED slots.
AssessmentTypePanel.java
Manage the list of assessment/check-up types.
Add new types, update description or status, find by ID. Duplicate names are rejected.
ReportsPanel.java
Two read-only reports: Hospital Metrics and Revenue Summary.
Metrics shows department/doctor/patient/schedule counts. Revenue shows billing totals from the Admin's bills.txt. A Refresh button reloads both.
Models — package model.manager
Department.java
Holds one department record (ID, name, specialty, status).
Validates that status is ACTIVE or INACTIVE. Converts to/from the pipe-delimited line format used in departments.txt.
DoctorSchedule.java
Holds one schedule slot (ID, doctorID, date, start, end, status).
Validates date as yyyy-MM-dd, times as HH:mm, and that end time is strictly after start time. Status: AVAILABLE / BOOKED / UNAVAILABLE.
AssessmentType.java
Holds one assessment type (ID, name, description, status).
Validates ACTIVE / INACTIVE status. Converts to/from the assessmentTypes.txt line format.
HospitalMetrics.java
Data carrier for the Hospital Metrics report.
Stores counts for departments, assessment types, schedule slots, doctors, patients. Also tracks which data sources are missing (modules not yet built by teammates).
RevenueSummary.java
Data carrier for the Revenue Summary report.
Stores total/paid/pending/unpaid bill counts and amounts. Computes outstanding = totalBilled − totalCollected.
Services — package service.manager
DepartmentService.java
Business logic for managing departments.
Reads/writes departments.txt via FileManager. Generates DEP-prefixed IDs via IDGenerator. Enforces unique names, non-empty fields, valid status. Retires (INACTIVE) instead of deleting.
AssessmentTypeService.java
Business logic for managing assessment types.
Same pattern as DepartmentService but for assessmentTypes.txt with AT-prefixed IDs.
DoctorScheduleService.java
Business logic for managing schedule slots.
Verifies that the doctor ID exists in doctors.txt (via DoctorService). Detects time overlaps. Generates SCH-prefixed IDs. Reads/writes doctorSchedules.txt.
ReportService.java
Produces the two analytical reports. Read-only — never writes any file.
Calls DepartmentService, AssessmentTypeService, DoctorScheduleService, DoctorService, UserManagementService, BillService. Reports missing data sources honestly instead of showing zeroes.
Data files — data/ folder (owned by my module)
departments.txt
Stores all hospital department records.
Format: departmentID|departmentName|specialty|status. Currently has 3 records (DEP001–DEP003).
doctorSchedules.txt
Stores all doctor schedule slots.
Format: scheduleID|doctorID|date|startTime|endTime|status. Currently has 4 records (SCH001–SCH004).
assessmentTypes.txt
Stores all assessment/check-up type records.
Format: assessmentTypeID|assessmentName|description|status. Currently has 3 records (AT001–AT003).

How to Run the HMS in Apache NetBeans

Opening the project

  1. Open Apache NetBeans.
  2. Go to File → Open Project.
  3. Navigate to C:\Users\ahmad\OneDrive\Documents\NetBeansProjects\HMS and click Open Project.
  4. The project will appear in the Projects panel on the left as HMS.

Checking the Java platform

  1. Right-click the HMS project → Properties.
  2. Under Libraries → Java Platform: confirm it shows a JDK. The project is configured for Java 26 (source compatibility). If NetBeans shows a warning about the platform, select the bundled NetBeans JDK from the dropdown.
  3. Click OK.

Running the application

  1. Press F6, or click the green Run Project ▶ button in the toolbar.
  2. NetBeans will compile all 46 source files and launch the application.
  3. The APU Medical Centre HMS — Login window appears.
ℹ️
If NetBeans asks which main class to use
Select main.Main. This is already set in nbproject/project.properties as main.class=main.Main, so it should never ask.

Stopping and re-running

  1. Close the HMS window (the X button or Logout → then close the Login window) to stop the app naturally.
  2. To re-run, press F6 again. NetBeans will only recompile if files have changed.
  3. If you need a clean rebuild: Run → Clean and Build Project (or Shift+F11), then F6.

Running from the built JAR (alternative)

A pre-built JAR already exists at dist/HMS.jar. You can run it from a terminal in the project folder:

"C:\Program Files\Apache NetBeans\jdk\bin\java.exe" -jar dist\HMS.jar

The working directory must be the project root so that the data/ folder is found at the expected relative path.

How to Use the HMS — User Flow

Login

  1. Enter Username: farahaziz
  2. Enter Password: manager123
  3. Click Login (or press Enter in the password field).
  4. The Medical Manager Dashboard opens with 5 tabs.

My Profile tab

  1. Click the My Profile tab (shown by default on login).
  2. The form loads: Manager ID = M001, Full Name = Farah Aziz, Username = farahaziz, Status = ACTIVE.
  3. To update the display name: edit the Full Name field and click Save Changes.
  4. Username, Status, and Password are read-only — those are set by Admin.
  5. Click Reload to discard unsaved changes.

Departments tab

  1. Click the Departments tab.
  2. The table shows all departments from departments.txt (currently DEP001–DEP003).
  3. To add: Fill in Name and Specialty, click Add. ID is auto-generated (DEP004 next).
  4. To update: Click a row → details load into the form → change name, specialty, or status → click Update.
  5. To find: Click Find by ID, type the ID (e.g. DEP001), and the row highlights in the table.
  6. To retire a department: Select it → change Status to INACTIVE → click Update. Records are never deleted.

Doctor Schedules tab

  1. Click the Doctor Schedules tab.
  2. Table shows all 4 current slots for Dr. Aisha Rahman (D001).
  3. To add a slot: Type Doctor ID (D001), Date (yyyy-MM-dd), Start and End times (HH:mm), click Add. The system checks the doctor exists and that the time slot does not overlap an existing one.
  4. To update a slot: Click a row → edit date/times/status → click Update. If the slot is BOOKED, it cannot be edited (patient appointment protection).
  5. To filter: Click Filter by Doctor and enter a Doctor ID. Click Show Available to see only bookable slots. Click Show All to reset.

Assessment Types tab

  1. Click the Assessment Types tab.
  2. Table shows all 3 current types (AT001–AT003).
  3. To add: Fill in Name and Description, click Add. ID auto-generated (AT004 next).
  4. To update: Click a row → edit name, description, or status → click Update.
  5. To find: Click Find by ID, type the ID.

Reports tab

  1. Click the Reports tab. Reports load automatically.
  2. Inside Reports there are two sub-tabs: Hospital Metrics and Revenue Summary.
  3. Hospital Metrics: Shows department count, assessment type count, doctor count, patient count, and schedule slot breakdown. Missing modules (appointments, medical records, feedback) are listed as "Not available yet" — this is expected.
  4. Revenue Summary: Shows bill counts and totals from bills.txt. Currently: 1 bill, RM 150.00 billed, RM 0.00 collected (bill is UNPAID), RM 150.00 outstanding.
  5. Click Refresh Reports to reload the latest data.

Logout

  1. Click the Logout button in the top-right of the dashboard.
  2. A confirmation dialog appears: click Yes.
  3. The dashboard closes and the Login screen returns.

Section 9

Important Notes & Limitations

⚠️
Three data sources are missing — this is intentional and expected The Hospital Metrics report lists these as "Not available yet" rather than showing zeroes:
  • appointments.txt — Patient module (not yet built by teammate)
  • medicalRecords.txt — Doctor module (not yet built by teammate)
  • feedback.txt — Patient module (not yet built by teammate)
When those modules are added, my report will automatically pick up the data — no changes to my code needed.
💡
Revenue shows RM 0.00 collected — correct behaviour The single bill (BILL001) is UNPAID. My Revenue Summary correctly shows RM 150.00 billed and RM 0.00 collected. The system only counts a bill as collected when it is marked PAID. This is not a bug.
💡
SCH002 is permanently BOOKED — cannot be edited My DoctorSchedulePanel blocks editing of BOOKED slots because a patient appointment is tied to that time slot. If you try to click Update on SCH002, the panel shows a warning. This is an intentional feature, not a bug. You can demonstrate it during the viva.
💡
Only one doctor in the system (D001 — Dr. Aisha Rahman) All 4 schedule slots are for D001. If you try to add a schedule for D999 or any other ID that does not exist in doctors.txt, the service rejects it with an error message. Doctor accounts are created by Admin Staff, not by the Medical Manager.
💡
Doctor / Department name consistency is free-text The Doctor record stores department = "Cardiology" as a free text string — it is not a foreign key to my DEP001. This is a known group design gap. The names happen to match today; there is nothing enforcing it automatically.
💡
Profile edit: only the display name is editable The username, password, and account status are created by Admin Staff and stored in users.txt. My ProfilePanel only edits the name in medicalManagers.txt. It never touches users.txt. This is by design.
💡
Doctor and Patient dashboards show an info message only Logging in as drrahman or amani shows a dialog saying the dashboard is implemented by another team member's module. This is expected — those modules are not yet complete.
